Roster snapshot

Baxter, the tournament manager, needs each player's number, name and current rating before an event — and must then be able to run a tournament with no connection to this site at all. This is the offline way to give it that: download the file, and load it into Baxter.

The file holds {{ player_count }} player{{ player_count|pluralize }}, {{ rated_count }} of them rated. A player with no rated games yet appears with a null rating; Baxter treats them as unrated, the same as this engine does.

Download {{ filename }} Download {{ csv_filename }}

The JSON file is the one Baxter reads. The CSV holds the same players, in the same order, for opening in a spreadsheet — checking the list over, or mailing it round.

What is in it

The player number, name, rating, deviation, career games and last-played date for every player — the coco.roster/1 document. Nothing else: the contact and administrative details held against a player are private and never appear in an export.

The player number is the identity. Names in the file are display data, and Baxter may overwrite its copy of them on every pull.
